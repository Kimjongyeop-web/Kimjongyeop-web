# 개발 기록

실행 중 확인한 문제와 수정 내용을 정리했습니다.

## 데이터 소스를 한투로 통합

초기에는 후보 순위와 과거 거래량에 pykrx를 사용했습니다. 이후 일봉 거래량을 한투 API로 전환했습니다.

시총 순위 API 응답이 30종목에 그쳐 필요한 50~150위 후보를 확보하지 못했습니다. 불완전한 순위로 매매하지 않도록 중단하고, 공개 전체 종목정보 파일에서 후보를 고르는 방식으로 바꿨습니다. 이 순위는 장중 실시간 값이 아닌 파일 기준값입니다.

## 분봉 부족과 추세 탈락 구분

데이터가 부족한 경우와 추세 조건에 맞지 않는 경우가 같은 문구로 표시됐습니다. 이를 분리해 대기 이유를 확인할 수 있게 했습니다.

3분봉은 완성된 고유 1분봉 3개로만 집계합니다. 중복·무효 행과 미완성 구간을 제외하고, OHLCV를 별도 계산과 대조했습니다. 시간 연산에서 발생하던 라이브러리 경고도 수정했습니다.

## 상태 로그 정리

종목별 반복 출력은 `--verbose`로 옮겼습니다. 기본 화면에는 준비 진행, 최근 수신 상태, 가상 보유·실현손익, 분봉 부족·추세 탈락·통과 수를 표시합니다. 오류와 거래 이벤트는 계속 출력합니다.

## 진입 조건 조정

여러 조건이 동시에 충족되는 경우가 적어 다음과 같이 조정했습니다.

| 항목 | 변경 |
|---|---|
| 돌파 기준 | 직전 20개 → 10개 분봉 |
| 거래량 증가율·양봉 몸통 | 기준 완화 |
| 고가 근접도 | 조건 제거 |
| 시장 대용 점수 | 추가 가중 제거 |
| 유지한 조건 | 3분봉 추세, 최소 거래량, 보유 한도, 손절·익절 |

한정된 과거 표본에서 신호 빈도 증가를 확인했습니다. 여러 거래일과 거래비용을 포함한 수익성 검증은 아직 하지 않았습니다.

## 기본 구조

실시간 시세 수신, 후보 탐색, 분봉 생성, 가상 포지션 저장, 알림 전송을 분리했습니다. 실계좌 주문 API는 사용하지 않습니다.

공개 파일은 코드, 설명, 합성 데이터 테스트입니다. 인증정보, 개인 실행 로그, 거래내역, 저장 분봉과 원본 데이터는 포함하지 않습니다.
